# API の入力・失敗・問い合わせの約束事

[0002](./0002-hono-api-server-with-server-side-authorization.md) で API を Hono とオニオンアーキテクチャにした。そのうえで、ユースケースとリポジトリをまたいで守っている約束事をここにまとめる。どれも API のテスト（`apps/api/src/test`）で押さえている。

## 失敗の返し方

- ユースケースは `application/errors.ts` のエラーを投げ、presentation がステータスコードに変える。`message` はそのまま利用者に見せるので、日本語で書く。レスポンスは `{ message }` とステータスコードにする。
- 本文が JSON として読めないときは、Hono が 400 を投げる。そのメッセージは英語なので、presentation で日本語に置き換える。
- 項目の型が違う、必須の項目がないなど、形が不正な入力は 422 にする。投稿の本文がない・文字列でないときも、空の本文と同じく 422 にする。
- 何かを作る操作の前提は、どの操作でも同じ順で確かめる（`application/require-login-user.ts`）。
  1. アカウントがユーザーを持っていなければ 403（新規ユーザー登録の前はできない）
  2. 対象（投稿やユーザー）がなければ 404
  3. 入力のルールに合わなければ 422
- 認可（投稿を消せるのは作者だけ、など）も前提の確認に含め、対象を取ったあと、入力を確かめる前に 403 にする。認可のある操作には専用の前提の関数（`requireDeletablePost` など）を作り、ユースケースは認可のルールを直接呼ばない。認可を渡し忘れても通る、省略できる引数にはしない。
- 取り消し（いいねやフォローを外す）とフォロー状態の問い合わせは、ユーザーのないアカウントでも通す（`requirePostEvenWithoutUser`・`requireTargetUserEvenWithoutUser`）。外すものがないので 204、フォロー状態は false になる。対象がなければ 404 にするのは同じ。
- 投稿とユーザーの ID は Postgres の `uuid` 型。UUID の形でない ID を渡すと DB がエラーにするので、リポジトリは問い合わせる前に形を確かめ、違えば「見つからない」として扱う。
- 存在しない投稿のコメント一覧は、404 ではなく空にする。詳細ページは投稿とコメントを並列に取るので、コメントのほうが失敗すると、投稿の 404 の表示にならない。

## 作る・消す操作

- フォローといいねは冪等にする。すでにあれば何もしない、なければ外しても何もしない。どちらも DB の一意制約で 1 つに保つ。
- ユーザーの ID はアカウントの ID と同じにする。
- ユーザーの編集は、渡された項目だけを確かめて変える。変える項目がなければ、update せずにいまの行を返す（drizzle は空の `set` を受け付けない）。
- プロフィール画像のアップロード先は、アカウントのフォルダの下に毎回新しい名前で発行する。新規ユーザー登録のフォームでも使うので、ユーザーがなくても発行できる。

## 検索と並び順

- 投稿とユーザーの検索は、大文字と小文字を区別しない。キーワードが空白だけなら何も返さない。キーワードの `\` `%` `_` は LIKE のワイルドカードとしてではなく、文字そのものとして一致させる。
- フォロワーとフォローの一覧は、フォローした順（古い順）に並べ、同じ時刻ならユーザー名順にする。

## レスポンスの形

- 投稿は、ログイン中のユーザーから見た形で返す。いいねは件数といいね済みかどうか（`like_count`・`is_liked`）、削除できるかどうか（`can_delete`）は domain の認可のルールで決める。web は認可のルールを持たず、`can_delete` を見て削除のメニューを出す。誰がいいねしたかの一覧は返さない。
- ユーザーのメールアドレスは、ログイン中のユーザー自身にだけ返す（`/me`）。投稿の作者、ユーザーの検索、フォロワーとフォローの一覧、プロフィールなど、ほかのユーザーが見るレスポンスには含めない。

## 実装上の制約

- 本番の DB には Supavisor のトランザクションモード（ポート 6543）でつなぐ。このモードはプリペアドステートメントに対応していないので、postgres.js に `prepare: false` を渡す。
- Hono のルートは、固定のパス（`/timeline`、`/search` など）を `/:postId`・`/:userId` より先に登録する。
- サブクエリから外側の行を指すときは、表名を付けて書く。JOIN のない select では `${users.id}` が表名なしの `"id"` になり、サブクエリの中の列と取り違える。サブクエリ側の `posts` には別名（`c`）を付ける。
