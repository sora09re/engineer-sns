# コメントを片付ける

このリポジトリの TS/JS にはコメントを書かない。`lint/no-comments.ts`（oxlint の `local/no-comments`）がこれを強制する。まだ残っているコメントは `lint/comment-baseline.json` にファイルごとの個数で記録してあり、**ラチェット**として扱う。個数は減らすだけで、増やさない。コメントの役目は次の場所が引き継ぐ。

- 判断の理由: `docs/adr/`
- 用語の定義: `GLOSSARY.md`
- 直すべき実装: GitHub Issues（`docs/agents/issue-tracker.md`）
- 振る舞いの仕様: テストの名前

`/delete-comment` に引数がなければリポジトリ全体を対象にする。パスが渡されたら、その下だけを対象にする。

## 1. 一覧を出す

```sh
pnpm comments list
```

出力は `### <file>:<line>` の見出しとコメントの本文。対象の範囲にあるコメントをすべて読み終えたら、この手順は終わり。トリプルスラッシュの `<reference>`、`@ts-expect-error`、`oxlint-disable*` などのディレクティブは一覧に出ない。これらは片付けの対象外。

## 2. 1 つずつ分類する

コメントの前後のコードを読み、次のどれか 1 つに決める。

| 分類                | 見分け方                                                                                                              | 行き先                      |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| **Tautology**       | 名前・型・テストの名前・`GLOSSARY.md`・既存の ADR を読めばわかる                                                      | 消す                        |
| **Stale**           | もうない実装、移行前のライブラリ（Biome、Next.js など）、変更の履歴（「追加:」「更新:」）、コメントアウトしたコード   | 消す                        |
| **Excuse**          | 場当たりの実装を正当化している（「〜まで直接書く」「まだ対応していない」「lint を黙らせる」「タイムアウトを延ばす」） | 消して、直す issue を立てる |
| **Decision Record** | コードからは読み取れない判断や制約で、消すと誰かが「直して」壊しかねないもの                                          | ADR に移してから消す        |

迷ったら、そのコメントを消した後に次の人がそのコードを書き換えて壊すかどうかで決める。壊しかねないなら Decision Record、壊さないなら Tautology にする。

すべてのコメントに分類と行き先を書いた表ができたら、この手順は終わり。表は PR の本文に載せる。

## 3. 行き先に移す

- **Decision Record**: テーマの合う既存の ADR（`docs/adr/`）があれば、そこに 1 項目として足す。合うものがなければ、次の番号で ADR を作る。1 つのコメントにつき 1 つの ADR にはせず、テーマごとにまとめる。書き方は既存の ADR に合わせる（日本語、`# 決めたこと` から書き、必要なら `## Considered Options` を付ける）。
- **Excuse**: 1 つの場当たりの実装につき 1 つの issue を立て、`needs-triage` を付ける。本文には、現状（ファイルと、消したコメントの趣旨）、やること、受け入れ条件を書く。同じ原因のコメントは 1 つの issue にまとめる。立てる前に `gh issue list` で同じ issue がないか確かめる。

Decision Record がすべて ADR に入り、Excuse がすべて issue 番号を持ったら、この手順は終わり。

## 4. 消す

```sh
pnpm comments delete <file> [<file>:<line> ...]
```

`<file>` を渡すとそのファイルのコメントをすべて消し、`<file>:<line>` を渡すとその行から始まるコメントだけを消す。行だけのコメントは行ごと、行末のコメントは前の空白ごと、JSX の `{/* */}` は波かっこごと消す。消したファイルは最後に `vp fmt` で整える。消した後は `git diff` を読み、コメントアウトされていたコードのように、消したことで表示や振る舞いが変わる箇所がないことを確かめる。

## 5. ベースラインを締める

```sh
pnpm comments baseline
pnpm check
pnpm typecheck
```

`lint/comment-baseline.json` の数は減るだけにする。`pnpm check` が通ったら終わり。消せずに残したコメントがあれば、その理由を PR の本文に書く。

## 減る行数の見積もり

残りを全部消したら何行減るかは、`git stash` を使わずに一時的なコミットか作業ツリーのコピーで `pnpm comments delete` を試し、`git diff --shortstat` の削除行数から挿入行数を引いて出す。
